# Ironlog

A personal hypertrophy and strength tracker for one lifter. It is used on a phone at the gym. It ships two ways from one source file: as a Claude artifact (a hosted single-page app with cloud sync) and as a standalone installable web app (dist/, hosted on GitHub Pages, offline, data on the phone). Since r24 every pull request is also published as a separate preview app at /preview/ (dist-preview/), to try on a phone before merging. Build r31.3, state schema v5.

## What is in this repo

- `index.html`: the whole app and the only source. One file of about 8,600 lines: CSS, markup, then one script in an IIFE. It has no build step and no framework. Chart.js 4.4.1 and SortableJS 1.15.2 load from cdnjs, with jsdelivr as fallback, and the fonts come from Google Fonts. three.js 0.159 (the 3D body) is imported as a module from jsdelivr or unpkg, only when the 3D view opens; the standalone build ships its own copy in `vendor/`.
- `tests/`: Playwright suites that drive the real page in Chromium. `tests/h.js` is the harness. It serves Chart.js, Sortable and the fonts from `node_modules`, blocks every other network call, and can fake the clock (`clock`), seed localStorage (`state`), and inject a mock cloud (`setup`).
- `scripts/build.js`: writes the standalone app to `dist/` (fonts and libraries copied in, manifest, icons, service worker); `--preview` writes the preview build to `dist-preview/`. `scripts/icons.py` draws the icons into `assets/`, and the preview's (the same mark over a striped band) into `assets/preview/`.
- `supabase/functions/delete-account/index.ts`: the server function behind Delete my account (pasted into the Supabase dashboard). `supabase/functions/feedback-to-issue/index.ts`: turns each feedback report into an issue in the private tickets repository (`FEEDBACK.md`). `.github/workflows/keepalive.yml`: a daily ping so the free project never pauses. `.github/workflows/publish.yml`: `npm test` on every pull request and push to `main`; a passing push to `main` publishes `dist/` to `gh-pages`.
- `scripts/cloud-supabase.js` and `supabase.config.json`: accounts and cloud sync for the standalone app. The build copies the script into dist/ as `cloud.js` with the supabase-js bundle, and injects the project URL and publishable key (both public; row level security protects the data). The secret key never goes in this repo. `SUPABASE.md` is the dashboard setup.
- `baselines/r11.html` to `r29.html`, and `r29-5.html` (r29.5), `r30.html`, `r30-2.html` (r30.2), `r31.html`, `r31-1.html` (r31.1) and `r31-2.html` (r31.2): previous published builds. `tests/migration.js` saves data with them and loads it into the current build. Never delete them. When you publish a new build, add the build it replaces here.

## Commands

```
npm install
npm run setup     # installs Chromium for Playwright (once)
npm test          # runs every suite, then the user-facing ones again on dist/; must end with "All suites passed"
npm run build     # writes dist/ only
```

Run a single suite with `node tests/<name>.js`. Each suite prints `ok`/`FAIL` lines, then `ALL PASS` (the fuzz suite prints `fuzz clean`).

## How the code is organised (search for these names)

- **New-install layout (r28):** `DEFAULT_HIDDEN` and `DEFAULT_ORDER` seed only a fresh state (`normalize(null)`: a new device, Erase everything, Sign out and remove). `normalize` reads a missing `autoDone` or `hidden` in an older save as the app behaved before (off, none), and adds `secOrder` after the other keys, as older builds do, so the synced settings keep one key order across builds (a different order made r21 and r28 phones rewrite each other's core; tests/r22.js caught it). `moreLine(tab)` ends a tab that has hidden sections (`secShow`, `goLayout`; `MORE_LIVE` skips sections that would be empty); `layoutDefault` and `layoutReset` go back to the defaults. Simple view (`SIMPLE_HIDE`) is gone. `demoKeep`/`demoRestore` (`KEY+'.demoSettings'`): demo data loaded on a first run puts the settings back when it is cleared.
- **State:** `freshState()`, `normalize()` and `STATE_VERSION`. `normalize()` runs on every load, import and cloud merge, and it validates every field. Any new field needs a default there. New optional fields stay `undefined` when unset, so existing record hashes don't change and cloud sync doesn't treat old records as edited. A migration is a `version < N` block that only adds data and never overwrites a value the user set.
- **Storage:** localStorage key `ironlog.v1`. **Cloud sync:** `cloudInit`, `cloudPull`, `cloudFlush`, `mergeChunk`, through `cloudProvider()` (Claude's db inside Claude, `window.ironlogCloud` in the standalone app). Data is split into `core`, `draft`, half-month session chunks `s-YYYY-MM-N` and, since r22, yearly body documents `b-YYYY` (bodyweights and measurements; `bodyChunkOf`), with a per-record three-way merge. Core still carries `bodyweights:[]` and `measurements:[]`, empty, in r21's key order, so an older build writes it back unchanged. Builds before r22 ignore `b-` documents and still write weigh-ins into core: `legacyBody`/`absorbLegacy` pick those up and move them; the first time a device sees a `b-` document its base comes from its pre-r22 core base (`legacyBodyBase`, `baseFor`), so deletes made on a device that updated first stay deleted. While an r21 phone is still in use, a delete or correction made on that phone is not applied on r22 phones (add-only pick-up); update every device.
- **Analytics:** `IDX()` builds everything once per change (`invalidate()` clears it): `byEx`, `exStats`, `weekSets`, `weekHard`, `dayMus`, `dayMeta`, `prs`, `scores`. Read from `IDX()` rather than recomputing, so the headline numbers and the detail sections can't disagree.
- **Math:** `e1` (Brzycki up to 10 reps to failure, Epley at 11–12, none above 12; sets above RIR 4 excluded), `e1inv`, `rtfAt`, `rtfBand`. `calStats` and `rirEff` handle RIR calibration: shrink n/(n+3), cap ±2, 12-week window, compound vs isolation, applied only to sets at RIR ≤ 4. Also `suggest` (double progression), `progStep` and `jumpCap`, `recovery`, `rankDays`, `rankExercises`, `setSecs`/`setupSecs`/`dayMinutes`.
- **Load meaning:** `loadMode` (each / total / side / stack / bw; an assisted lift, `ex.assist`, is a bw lift whose sets store bodyweight minus the machine's help as a negative `w`: the field shows and takes the help as a plain number via `loadIn`, labels read BW−40, and `suggest` lowers the help to progress and raises it for a deload; `normalize` allows `w` down to −300 for this), `loadWords`, `loadNote`, `loadHead`, `lmChips`, `tonnage`. Every set stores the number exactly as typed. Estimates and targets stay in that frame, and tonnage counts what actually moved.
- **UI:** `render()` rebuilds `#view` from strings, with the views `viewToday`, `viewLogger`, `viewProgram`, `viewDash`, `viewHistory`, `viewSettings`. `sec()` is the one foldable section component; every section starts folded each visit except Sessions on History (`MAIN_FIXED`, `openMain`). Since r28 a section's explanation is `helpLink` (How this works) as the first line inside it, never a ? in the header beside the arrow; folds inside a section (`.subsec`) sit on their own surface. Actions are `data-act="name"` handled in the `ACT` object. `renderModal`/`renderModalBody` draw the sheets and keep their scroll and focus across re-renders.
- **Look:** tokens on `:root` (light) and the dark blocks. The Today card uses `--hero`, `--on-hero`, `--hero-bg`, `--hero-ring` and `--hero-shadow`, light in the light theme since r21; the rest-timer bar uses `--dock`, `--on-dock` and `--dock-bg`, inked in both themes. `--volt` is the accent and means go, done and progress; `--volt-line` is its thin-line form. The accent is chosen in Settings > General (`ACCENTS`: Blue, the default, Volt, Ember) and applied as `data-accent` on `<html>`, which swaps `--volt`, `--on-volt`, `--volt-line`, `--volt-soft` and, for Blue, turns "above target" (`--blue`) violet so it never reads as done. Gold (`--gold`) is only for PRs. Green, amber, blue and red keep their meanings. Dark is the default for new installs. The r20 design layer: `--btn`, `--field`, `--card-b`, `--glass`, `--hero-bg`; sections unboxed with sentence-case titles; frosted header and tabs.
- **Undo:** `snapshot(inv)` records the state before an action; the first save after it records the result. Since r22 the stack is kept in IndexedDB (`ironlog-undo`, `undoPersist`, `undoRestore` on boot, entries over 7 days dropped), so Undo in Settings works after the app is reopened; `inv` functions are not stored, those entries undo through the merge. `undoForget` clears it when a signed-out phone removes its log. `ACT.undo` runs `inv` when given (in-session actions: remove exercise, remove logged set, swap), else a three-way merge (per exercise for the session in progress, `mergeDraft`), so work logged after the action survives.
- **Targets per day's range (r27):** `suggest` reads the sessions logged in the exact rep range the plan asks for (`rr`), so a lift on a heavy and a light day progresses per day, while that range is in use (its newest session within 42 days of the newest full session); sessions with no range on record go with them. Otherwise, a range new or not used lately, it reads every full session (the newest wins). The Last line follows the same choice. `planFor(exId,R,dayId)` prefers the day being trained.
- **Well past the range (r27):** every top set 2+ reps over repMax (a range moved down) sets the load from the e1RM estimate for the middle of the range, capped by `jumpCap`, whole steps; since r31 `fitE` reads sets past 12 reps to failure with Epley up to 30 for this, so a set of 25 still sets the load. A load step of 0 is a fixed load (the at-cap reps branch, `capped` only at a real cap).
- **Grey reps after a new load (r27):** when `b.tgt.kind==='load'`, `greyR` skips last time's reps (they were at the old load) and uses the set above, else the target's repMin.
- **Steps and lighter loads (r27):** `stepRead`/`unitStep`: either unit's default (5 lb or 2.5 kg) reads as the current unit's; any other step as typed. `lighterLoad(ex,plan,from,to)` steps down from `from` in whole steps of `incOf` (never under the bar on a compound barbell lift typed as the total), used by deloads, warm-ups (inserted after the existing ones, climbing) and drop sets.
- **Changes reach the session (r27):** `refreshEx(exId)` (load step sheet, heaviest load, exercise editor) and `syncDraftPlan(f)` (a Plan item's range, RIR, rest or step, on the day being trained) re-read targets for exercises with no set done; typed loads are never touched. `swapPlan(p,from,to,R,dayId)` gives a swapped-in exercise its routine plan, or its own default when timed differs, else the slot's; set count kept.

## Rules for changes

1. Don't break what works. Run `npm test` before and after. Add or extend a suite for every behaviour you change.
2. Never lose data. Any change to stored shape needs a `normalize()` default, and a migration if it changes meaning, plus a case in `tests/migration.js`.
3. The math follows the evidence review summarised under "Evidence base" below. Don't change a number without a source. Label conventions as conventions, in a tip.
4. Copy is short, plain and specific. No em dashes, no hype, no exclamation marks. The default screen shows the number and the action; the reasoning goes in a `data-tip` or a `?` help toggle.
5. Phone first: 44 px touch targets, no horizontal overflow at 320 px, and light and dark both checked. `tests/charts-layout.js` checks overflow.
6. Code comments explain why, not what, in full sentences. That is the house style of this file.
7. Bump `APP_VERSION` for every published build, and `STATE_VERSION` only when the stored shape changes.

## Evidence base (behind the r13 corrections)

- **1RM:** Brzycki up to 10 reps to failure, Epley at 11–12 (they agree at 10). Nuzzo 2024 and Halperin 2022 on how estimates spread at higher reps.
- **Hard sets:** RIR ≤ 3 (Robinson 2024, Refalo 2023).
- **Target RIR of 1 (a convention, r29.5):** hypertrophy improves as sets end closer to failure (Robinson 2024, Sports Medicine meta-regressions), but training to failure grew the quadriceps no more than stopping at 1 to 2 RIR in trained lifters, with more velocity and rep loss (Refalo 2024, J Sports Sci). 1 sits between; templates use 0 on some isolation lifts and 2 on some heavy or bodyweight lifts. Helper muscles count 0.5 (Pelland 2025).
- **Blank RIR (a convention, r20):** RIR is optional. A blank is read as the lift's usual RIR, the median of its rated working sets in the last 12 weeks once there are 3 (`rirUsual`, `rirEst`), for e1RM, PRs, stalls and hard sets; with fewer, it counts as hard and as 0 for estimates (errs low). Recovery, calibration and the light-load recalibration read only entered RIR. People under-call reps left by about 1 on average (Halperin 2022), so a called 0 is kept as a call.
- **Weekly and per-session volume:** major-muscle bands of 10–20 are typical, not a ceiling. The per-session flag sits above 11 sets (Remmert 2025, preprint).
- **Deloads** round down to a loadable step, so they never land back on the full load: whole steps of the exercise's own step, never under the bar on a compound barbell lift typed as the total (r27; curls on EZ or fixed bars and per-side numbers have no floor).
- **Well past the range (a convention, r27):** uses the same e1RM estimate and 10% cap (`jumpCap`) as the RIR recalibration; no new number.
- **Moving and stalls:** "moving" needs ≥ 3% and a slope whose two-sided 80% interval (Student's t, n−2 degrees of freedom; `t90`) is above zero; estimated 1RM varies 2–8% day to day (Sigvaldsen 2023). Muscle trends count only lifts that are moving or falling. A stall is a flat or falling slope over the last 6 sessions, widened to cover ≥ 21 days when 6 do not (at least 4 sessions).
- **Recovery tiers:** 1, 2 or 3 days by set count, +1 day after failure sets or a new lift, +0.5 after heavy hinges, Nordics or walking lunges, −1 if every set stopped at RIR ≥ 3. This is a rule of thumb, used only for ranking.
- **Training blocks and trends (conventions, r30):** a session is read as lighter at 10% or more under the load of its previous three and 7% or more under their reps-alone reading (a deload is usually about 10% off; day-to-day swings in estimated strength are 2 to 8%, Sigvaldsen 2023). RIR enters a trend only when rated on 80% or more of a lift's sets. Trends read up to 20 reps to failure with Epley (formulas spread past 12, so never shown as a 1RM, but one lift against itself at similar reps still shows direction). A rep PR counts at 90% or more of the strongest set before it. An exercise with fewer than half its sets done is trimmed. A harder bodyweight swap (`HARD_EX`) gets 3 to 6 reps. None of these moves a number in the evidence above.
- **Tracked-only muscles (a convention, r29):** serratus, rotator cuff, neck and tibialis (`TRACK_ONLY`) are counted and shown with no target: no study sets a weekly dose for them, and most routines leave them to indirect work.
- **First-run targets (a convention, r29):** picking a ready-made routine on a first run lowers each weekly minimum to what it plans, only while every target is still the default and never raising anything; targets the lifter set are left alone. It moves no number in the evidence; it says the plan is the lifter's target, and the toast says so.
- **Second review conventions (r31):** the working load is the load done for the most sets among loads at 60% or more of the session's heaviest; flat is under 0.1% a week; a new level is lighter sessions in a row over 2 weeks or more; a trend needs 3 sessions over 2 weeks; load-finding reads sets past 12 reps to failure with Epley up to 30 (never shown) and allows a 25% jump in a lift's first 3 sessions; only compound lifts with an estimate count toward a deload suggestion; a routine made from an import uses the common ranges nearest the usual reps (1-3, 3-5, 6-8, 8-10, 10-12, 12-15, 15-20). None moves a number in the evidence above.
- **Bodyweight share:** only the push-up figure is measured (64%, Ebben 2011); the rest are segment-mass estimates.
- **Waist-to-height:** 0.5 / 0.6 bands (NICE 2022).
- **Tape measurements:** changes under about 1 cm are treated as noise.
- **Long-length bonus:** only for exercises backed by trials (seated leg curl, overhead triceps, standing calf raise) or by mechanics (labelled as such).
