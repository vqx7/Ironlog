# Ironlog

A personal hypertrophy and strength tracker for one lifter. It is used on a phone at the gym. It ships two ways from one source file: as a Claude artifact (a hosted single-page app with cloud sync) and as a standalone installable web app (dist/, hosted on GitHub Pages, offline, data on the phone). Since r24 every pull request is also published as a separate preview app at /preview/ (dist-preview/), to try on a phone before merging. Build r26, state schema v5.

## What is in this repo

- `index.html`: the whole app and the only source. One file of about 6,900 lines: CSS, markup, then one script in an IIFE. It has no build step and no framework. Chart.js 4.4.1 and SortableJS 1.15.2 load from cdnjs, with jsdelivr as fallback, and the fonts come from Google Fonts. three.js 0.159 (the 3D body) is imported as a module from jsdelivr or unpkg, only when the 3D view opens; the standalone build ships its own copy in `vendor/`.
- `tests/`: Playwright suites that drive the real page in Chromium. `tests/h.js` is the harness. It serves Chart.js, Sortable and the fonts from `node_modules`, blocks every other network call, and can fake the clock (`clock`), seed localStorage (`state`), and inject a mock cloud (`setup`).
- `scripts/build.js`: writes the standalone app to `dist/` (fonts and libraries copied in, manifest, icons, service worker); `--preview` writes the preview build to `dist-preview/`. `scripts/icons.py` draws the icons into `assets/`, and the preview's (the same mark over a striped band) into `assets/preview/`.
- `supabase/functions/delete-account/index.ts`: the server function behind Delete my account (pasted into the Supabase dashboard). `supabase/functions/feedback-to-issue/index.ts`: turns each feedback report into an issue in the private tickets repository (`FEEDBACK.md`). `.github/workflows/keepalive.yml`: a daily ping so the free project never pauses. `.github/workflows/publish.yml`: `npm test` on every pull request and push to `main`; a passing push to `main` publishes `dist/` to `gh-pages`.
- `scripts/cloud-supabase.js` and `supabase.config.json`: accounts and cloud sync for the standalone app. The build copies the script into dist/ as `cloud.js` with the supabase-js bundle, and injects the project URL and publishable key (both public; row level security protects the data). The secret key never goes in this repo. `SUPABASE.md` is the dashboard setup.
- `baselines/r11.html` to `r25.html`: previous published builds. `tests/migration.js` saves data with them and loads it into the current build. Never delete them. When you publish a new build, add the build it replaces here.

npm install
npm run setup     # installs Chromium for Playwright (once)
npm test          # runs every suite, then the user-facing ones again on dist/; must end with "All suites passed"
npm run build     # writes dist/ only

## How the code is organised (search for these names)

- **State:** `freshState()`, `normalize()` and `STATE_VERSION`. `normalize()` runs on every load, import and cloud merge, and it validates every field. Any new field needs a default there. New optional fields stay `undefined` when unset, so existing record hashes don't change and cloud sync doesn't treat old records as edited. A migration is a `version < N` block that only adds data and never overwrites a value the user set.
- **Storage:** localStorage key `ironlog.v1`. **Cloud sync:** `cloudInit`, `cloudPull`, `cloudFlush`, `mergeChunk`, through `cloudProvider()` (Claude's db inside Claude, `window.ironlogCloud` in the standalone app). Data is split into `core`, `draft`, half-month session chunks `s-YYYY-MM-N` and, since r22, yearly body documents `b-YYYY` (bodyweights and measurements; `bodyChunkOf`), with a per-record three-way merge. Core still carries `bodyweights:[]` and `measurements:[]`, empty, in r21's key order, so an older build writes it back unchanged. Builds before r22 ignore `b-` documents and still write weigh-ins into core: `legacyBody`/`absorbLegacy` pick those up and move them; the first time a device sees a `b-` document its base comes from its pre-r22 core base (`legacyBodyBase`, `baseFor`), so deletes made on a device that updated first stay deleted. While an r21 phone is still in use, a delete or correction made on that phone is not applied on r22 phones (add-only pick-up); update every device.
- **Analytics:** `IDX()` builds everything once per change (`invalidate()` clears it): `byEx`, `exStats`, `weekSets`, `weekHard`, `dayMus`, `dayMeta`, `prs`, `scores`. Read from `IDX()` rather than recomputing, so the headline numbers and the detail sections can't disagree.
- **Math:** `e1` (Brzycki up to 10 reps to failure, Epley at 11–12, none above 12; sets above RIR 4 excluded), `e1inv`, `rtfAt`, `rtfBand`. `calStats` and `rirEff` handle RIR calibration: shrink n/(n+3), cap ±2, 12-week window, compound vs isolation, applied only to sets at RIR ≤ 4. Also `suggest` (double progression), `progStep` and `jumpCap`, `recovery`, `rankDays`, `rankExercises`, `setSecs`/`setupSecs`/`dayMinutes`.
- **Load meaning:** `loadMode` (each / total / side / stack / bw; an assisted lift, `ex.assist`, is a bw lift whose sets store bodyweight minus the machine's help as a negative `w`: the field shows and takes the help as a plain number via `loadIn`, labels read BW−40, and `suggest` lowers the help to progress and raises it for a deload; `normalize` allows `w` down to −300 for this), `loadWords`, `loadNote`, `loadHead`, `lmChips`, `tonnage`. Every set stores the number exactly as typed. Estimates and targets stay in that frame, and tonnage counts what actually moved.
- **UI:** `render()` rebuilds `#view` from strings, with the views `viewToday`, `viewLogger`, `viewProgram`, `viewDash`, `viewHistory`, `viewSettings`. `sec()` is the one foldable section component. Actions are `data-act="name"` handled in the `ACT` object. `renderModal`/`renderModalBody` draw the sheets and keep their scroll and focus across re-renders.
- **Look:** tokens on `:root` (light) and the dark blocks. The Today card uses `--hero`, `--on-hero`, `--hero-bg`, `--hero-ring` and `--hero-shadow`, light in the light theme since r21; the rest-timer bar uses `--dock`, `--on-dock` and `--dock-bg`, inked in both themes. `--volt` is the accent and means go, done and progress; `--volt-line` is its thin-line form. The accent is chosen in Settings > General (`ACCENTS`: Blue, the default, Volt, Ember) and applied as `data-accent` on `<html>`, which swaps `--volt`, `--on-volt`, `--volt-line`, `--volt-soft` and, for Blue, turns "above target" (`--blue`) violet so it never reads as done. Gold (`--gold`) is only for PRs. Green, amber, blue and red keep their meanings. Dark is the default for new installs. The r20 design layer: `--btn`, `--field`, `--card-b`, `--glass`, `--hero-bg`; sections unboxed with sentence-case titles; frosted header and tabs.
- **Undo:** `snapshot(inv)` records the state before an action; the first save after it records the result. Since r22 the stack is kept in IndexedDB (`ironlog-undo`, `undoPersist`, `undoRestore` on boot, entries over 7 days dropped), so Undo in Settings works after the app is reopened; `inv` functions are not stored, those entries undo through the merge. `undoForget` clears it when a signed-out phone removes its log. `ACT.undo` runs `inv` when given (in-session actions: remove exercise, remove logged set, swap), else a three-way merge (per exercise for the session in progress, `mergeDraft`), so work logged after the action survives.
- **Last time and targets (r26, V's rule):** `lastOf(all,base,fmt)` builds the Last line from the most recent session with the exercise, whatever it was, and labels it trimmed, lighter or deload. Targets still come from the last full session (`suggest` skips cut, lighter and deload sessions); when that is an earlier session, the block keeps its date in `basis` and the target shows a tip naming it. Last time's reps follow the shown session, except after a deload, whose reps were cut on purpose.
- **Last time's reps:** `lastRFor(b,si)` maps a row to last session's working sets (warm-ups and drop sets excluded); never index `lastR` by row.
- **Past workouts (r21):** `ACT.pastOpen` (an empty past day in the week bar, or History's Log a past workout) opens `pastSheet`: a date, then the routine day that was due (`pastDue`, from `cycleState(R,asOf)`, or the weekday) first, other training days, Freestyle. `pastDraft` builds a draft with `past:true`, `startedAt:null` and blocks from `newBlock(...,{before:date})`. `suggest(...,{before})`, `livePR(exId,s,date)` and `lastNoteOf(exId,before)` read only sessions up to that date (`statsUpTo` rebuilds the bests). Quick entry: no check-in, no rest timer or its buttons, typed reps tick the set. Changing a draft's date re-reads its targets (`refreshBlock`). Sessions sort by date everywhere, so one entered late lands in order.
- **Grey reps and Discard (r21):** `greyR(b,si)` is the number an empty reps field shows and the checkmark, auto-mark and the keyboard's Done take: last time's reps, else the working set above in this session, else the bottom of the planned range; `refreshGrey` updates it as reps are typed. `draftEntered(d)` says whether anything was put in (ticks, typed reps, cardio minutes, exercise notes, session notes other than `note0`, the text the app wrote); Discard (top and beside Finish) and replacing a session ask only then.
- **Logger flow:** a finished exercise folds to one line (`blockDone`, `autoFold`, `ui.blkOpen`); ticking done on an empty reps field logs last time's reps (`lastR`); RIR is a 0 to 5 strip (`rirSelect`, `rirShowStrip`, `ACT.rirPick`) that opens when the set's RIR box is tapped, and after each ticked set only when `settings.rirAsk` is on. Loads come prefilled from `suggest()`; with no history, a load typed on a working set fills the empty loads below it (`carryLoad`, and rows it filled follow a correction). Auto-mark (`settings.autoDone`, off by default): typing reps and leaving ticks the set; leaving an empty reps field (Next, the iPhone keyboard's Done, a tap on blank space) accepts the grey number (`acceptGrey`, the `focusout` handler); moving within the row or tapping a button does not. `rebuilding` is true while `#view` is replaced, so the change the browser fires for a removed focused field never ticks a set. − Set on a row with reps typed, and removing a filled cardio entry, give an Undo; empty ones go quietly.
- **Updates (standalone app):** the service worker made by `scripts/build.js` precaches past the HTTP cache, and a new version waits instead of taking over. The build's boot script calls `ironlogUpdateReady()`, which shows `#updbar` ("New version ready", Reload, Later); Reload saves, then `ironlogApplyUpdate()` lets the waiting worker take over and the page reloads once. It also checks for updates whenever the app returns to the foreground.
- **Privacy:** `privacyLine()` in Settings > Your data says where the log lives and who can see it: this device, the Ironlog account (you and the app owner), or the Claude account inside Claude.
- **Waiting for confirmation (r21):** after sign-up the account sheet is in mode `wait`: `waitStart` keeps the email and password in memory only (`acctWait`) plus a marker without the password (`KEY+'.acctWait'`), and `waitTry` signs in on returning to the front, on "I have confirmed", and every 20 s (60 s after 5 minutes, stops at 30). Closing the sheet forgets it. A confirmation link opened in a browser asks `where` (`ACT.acctWhere`: `app` signs that browser out, `here` calls `ironlogAuth.release()` and syncs); no answer signs it out; if the marker is in that storage it signs in without asking.
- **Feedback (r21, reworked r25):** `fbSheet`, `ACT.fbOpen` (Settings > Feedback, an exercise's ⋯ menu), `fbContext` (what is attached: never workouts), `fbShrink` (screenshot to a 1280 px JPEG), `ACT.fbSend` through `window.ironlogFeedback` (defined in `scripts/cloud-supabase.js`), or a copy of the report where there is none. `acct.reader` (from `fbCheckReader`) shows the owner's Inbox (`fbInboxSheet`). See `FEEDBACK.md`.
- **Accounts (standalone app):** the app only looks for `window.ironlogAuth` (`AUTH()`) and `window.ironlogCloud`; `scripts/cloud-supabase.js` defines both. `acctInit`, `acctPanel`, `acctSheet` (modes signin, signup, forgot, newpw, sent), `ACT.acctSubmit`, `ACT.acctSignOut` (keep or remove the phone's copy), `cloudStop`. Signed out, the account is offered on the first-run welcome card and as a slim line on Today (`acctBar`, hidden per device by Not now). Sync notes carry the account id (`cloud.acct`): a different account on the same device starts over as a first link. An emailed link opened in a browser (not the installed app) is handled there, then that browser is signed out again so it never uploads what it holds. Accounts are optional; without one nothing changes. The emailed sign-in link option was left out on purpose: on an iPhone it opens in Safari, whose storage is separate from the home-screen app.
- **Breached passwords (r26):** Supabase's Leaked Password Protection is a Pro plan feature, so `scripts/cloud-supabase.js` checks itself: `breached(password)` sends the first 5 characters of the password's SHA-1 hash to Have I Been Pwned's range API (with `Add-Padding`), and `signUp` and `updatePassword` refuse a match with `code:'breached'`. Any error or a wait over 3 s lets the password through, so an outage never blocks sign-up.
- **Standalone app:** `isStandalone()` switches export to the share sheet (Save to Files) and the storage wording. `cloudProvider()` takes Claude's db inside Claude, else `window.ironlogCloud` (`{db, userId}` with the same doc/collection calls), and sync, merging and chunking work unchanged.
- **Comeback (former bests):** removed in r19 at the owner's request, with the saved former bests: `normalize()` deletes `priors` from every load, import and merge.
- **Back gesture:** `navSync()` (called from `render()`) adds a history entry per tab change; `popstate` closes a sheet first, else shows the entry's tab (`ilTab`). A sheet's leftover entry is replaced by the next tab change.
- **First run (r22):** a new install opens on its own pages instead of Today (`obActive`, `obView`; `body.obmode` hides the header and tabs). Page 1, only where accounts exist: Save your log (Create account, I have an account, Not now; `OB_ACCT` per device, `ACT.obAcctLater`/`obAcctBack`). Page 2, Set up: optional name, units (`ACT.obUnit`), then Pick a ready-made routine, Log a workout now, Build my own routine, Import a backup (`#importFile`), and Look around with sample data. Any session, demo data, a draft, or a sign-in that brings a log ends it; while the device is still finding out, a splash shows instead. `welcomeCard` now only shows the demo note.
- **PRs (r22):** the PR feed records what each PR beat (`prev` for a best estimate, `prevR` for a rep PR). A PR set gets a gold toast with that (`prBeat`, `toast(...,'pr')`), a gold pulse on the row (`.prflash`, off with reduced motion) and a buzz where allowed; the recap opens with a gold block (`#recapPR`). Stats > Lifts > All-time bests (`bestsBoard`, `allTimeBests`): per lift the best estimate, the heaviest set, and the rep records (most reps at each load where no heavier set did as many, with the date first reached), newest record first; six lifts show, Show all (`ui.bestsAll`) lists the rest.
- **Importing (r23):** `impStart` reads a file or pasted text: an Ironlog backup goes to `importData` (restore), a table (`impRows` CSV/TSV, `impXlsx` via DecompressionStream) goes through `impHeader` (`IMP_COLS`, best header first) and `impFromTable` (Strong, Hevy, hand-made sheets, Ironlog's CSV), anything else through `impFromText` (notes, built on `parseSets` with `impSetsText`). `openPreview` matches names (`impMatch`: `impNorm` synonyms, `IMP_ALIAS`, equipment and modifier words) and `impSheet` shows counts, the unit, exercise choices (or a new custom exercise with a muscle), what was read, lines not understood, skipped rows and duplicates. `impBuild` makes freestyle sessions in kg and skips ones already in the log; `ACT.impGo` saves through `normalize` with Undo. Nothing is saved before the preview.
- **Header (r23):** the wordmark left the bar (`.vh` keeps it for screen readers); the days touch, so each is at least 44 px wide from 375 px phones up. This week owns this week (sessions in the header, hard sets against planned, weight lifted in `liftedLine`); At a glance keeps the streak and PRs, whose tile opens All-time bests.
- **Name and routines:** `settings.userName` (optional, 40 characters) shows a greeting on Today. `TEMPLATES` holds the ready-made routines (full body 3, upper/lower 4, PPL 6, body-part split 5, dumbbells 3, and the starter high-volume routine); `routineFromTemplate()` copies one with new ids. The sheet opens from the welcome card (replaces the untouched starter) and from Plan (adds, and opens the existing copy instead of a duplicate, by `routineSig`).
- **3D body:** `B3`, `mount3D`, `map3dLoad` (imports three.js from `THREE_URLS`), `B3_PARTS` shapes; each muscle region is shaded by this week's sets and picked by raycast. The flat map stays.
- **Install:** `installBar`, `installSheet`, `installPic`, `ACT.install`, `installLater`. The build's head script sets `window.IRONLOG_APP` and captures `beforeinstallprompt`. `installKind()` tells Safari 26 (Share behind ⋯ beside the address), older Safari, Chrome and other iPhone browsers apart; iPhones get "Add to Home Screen", a picture of where to tap and two steps, with the reasons in a tip. On Today the account line comes first, Install second.
- **Tips:** any element with `data-tip` shows it on mouse hover (350 ms), keyboard focus, or a touch hold (480 ms; the click that follows is swallowed). `tipi(text)` makes a small "i" button that shows its tip on a tap. Long explanations go here, not on screen.
- **Preview build (r24):** `node scripts/build.js --preview` sets `window.IRONLOG_ENV='preview'`, and `ENV` in the app. It shares the live app's origin (vqx7.github.io), so everything stored is kept apart by name: `KEY` is `ironlog-preview.v1` (every other key derives from `KEY`), the undo database `ironlog-preview-undo`, the sign-in slot `ironlog-preview.auth` and the sync table `docs_preview` (in `scripts/cloud-supabase.js`), and caches start `ilpreview-` (the live worker clears every other `ironlog-` cache). The live worker leaves navigations under `preview/` to the network, so the preview page can load and install its own worker (scope `preview/`). Name "Ironlog Preview", home-screen label "Preview", striped icon, a labelled PREVIEW tag on the tab bar (r25; the striped edges read as stray dotted lines), "Ironlog Preview" in Settings. No Delete my account in the preview (it would delete the real account). Feedback context carries `env`.
- **Swap and suggestions (r24):** a swap takes its set count from the rows the exercise has now, not the routine's plan, and keeps `cut`. Each block stores the load the app suggested (`sw`, null when none; absent in drafts from before r24); `refreshBlock` (a date change, a new heaviest load) replaces only rows still on that suggestion, so a typed load is never overwritten.

## Rules for changes

1. Don't break what works. Run `npm test` before and after. Add or extend a suite for every behaviour you change.
2. Never lose data. Any change to stored shape needs a `normalize()` default, and a migration if it changes meaning, plus a case in `tests/migration.js`.
3. The math follows the evidence review summarised under "Evidence base" below. Don't change a number without a source. Label conventions as conventions, in a tip.
4. Copy is short, plain and specific. No em dashes, no hype, no exclamation marks. The default screen shows the number and the action; the reasoning goes in a `data-tip` or a `?` help toggle.
5. Phone first: 44 px touch targets, no horizontal overflow at 320 px, and light and dark both checked. `tests/charts-layout.js` checks overflow.
6. Code comments explain why, not what, in full sentences. That is the house style of this file.
7. Bump `APP_VERSION` for every published build, and `STATE_VERSION` only when the stored shape changes.

## Evidence base (behind the r13 corrections)

- **1RM:** Brzycki up to 10 reps to failure, Epley at 11–12 (they agree at 10). Nuzzo 2024 and Halperin 2022 on how estimates spread at higher reps.
- **Hard sets:** RIR ≤ 3 (Robinson 2024, Refalo 2023). Helper muscles count 0.5 (Pelland 2025).
- **Blank RIR (a convention, r20):** RIR is optional. A blank is read as the lift's usual RIR, the median of its rated working sets in the last 12 weeks once there are 3 (`rirUsual`, `rirEst`), for e1RM, PRs, stalls and hard sets; with fewer, it counts as hard and as 0 for estimates (errs low). Recovery, calibration and the light-load recalibration read only entered RIR. People under-call reps left by about 1 on average (Halperin 2022), so a called 0 is kept as a call.
- **Weekly and per-session volume:** major-muscle bands of 10–20 are typical, not a ceiling. The per-session flag sits above 11 sets (Remmert 2025, preprint).
- **Deloads** round down to a loadable step, so they never land back on the full load.
- **Moving and stalls:** "moving" needs ≥ 3% and a slope whose two-sided 80% interval (Student's t, n−2 degrees of freedom; `t90`) is above zero; estimated 1RM varies 2–8% day to day (Sigvaldsen 2023). Muscle trends count only lifts that are moving or falling. A stall is a flat or falling slope over the last 6 sessions, widened to cover ≥ 21 days when 6 do not (at least 4 sessions).
- **Recovery tiers:** 1, 2 or 3 days by set count, +1 day after failure sets or a new lift, +0.5 after heavy hinges, Nordics or walking lunges, −1 if every set stopped at RIR ≥ 3. This is a rule of thumb, used only for ranking.
- **Bodyweight share:** only the push-up figure is measured (64%, Ebben 2011); the rest are segment-mass estimates.
- **Waist-to-height:** 0.5 / 0.6 bands (NICE 2022).
- **Tape measurements:** changes under about 1 cm are treated as noise.
- **Long-length bonus:** only for exercises backed by trials (seated leg curl, overhead triceps, standing calf raise) or by mechanics (labelled as such).
