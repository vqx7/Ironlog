# Architecture

Where Ironlog's code is going, how it gets there, and the rules that hold on the way. Written in r49 (V, 2026-10-16: real modules, one source for every value, no hard-coding, built like a professional codebase). PENDING item 303 tracks it.

## Why

Ironlog started as a Claude artifact, which has to be one HTML file. When the artifact was retired on 2026-09-27 the code stayed in that shape: one script, every function and value in one shared scope, screens built from HTML strings. r36 cut it into 24 files, but they are pieces of one script, not modules. In that shape any part can read or change any other part, a value can be typed in many places, and nothing but the tests stops either. Typed modules with clear boundaries stop both before the app runs.

## Where it ends

```
src/app/            TypeScript modules, the whole app when this is done
  config.ts         names, versions, addresses: every value defined once (r49)
  types.ts          record shapes: an exercise, a plan item, a set, a session's blocks (r50, r51)
  util.ts           text, ids, dates, numbers, the sync hash, seeded randoms (r50)
  units.ts          units and plates (r50)
  library.ts        muscles, joints, equipment, the exercise library, search (r50)
  routines.ts       the default plan, the ready-made routines, routine helpers (r50)
  formulas.ts       the 1RM estimate, working load, set counting, time (r50)
  store.ts          the shared state: state (replaced by setState), ui, cloud, acct (r51)
  records.ts        the schema version, limits, id checks, record cleaners (r51)
  chunks.ts         the sync documents; merge.ts, the three-way merge (r51)
  session.ts        a session in progress: grey loads, live targets, the Last column (r51)
  profile.ts        Your training; gym.ts, Your gym (r51)
  loads.ts, prs.ts, trend.ts, volume.ts, goals.ts, charts.ts   words and windows the screens share (r51)
  format.ts, layout.ts, icons.ts, feedback.ts, importing.ts    dates and durations, sections, icons, reports, import parsers (r51)
  ...               one module per area, in the order of the phases below
src/01-03, 99       the page's markup and styles
```

- **TypeScript**, strict, checked on every test run (`tests/hygiene.js`).
- **esbuild** bundles it into the one inline script the page needs. Every suite opens the page as a file, where module scripts are refused, and the installed app's Content Security Policy fingerprints each inline script, so the output stays one inline script. A larger toolchain such as Vite (a dev server, with Rollup or Rolldown for production) would add nothing this app uses.
- **Modules with one-way dependencies**: config at the bottom, then data, engine and analytics (pure functions of their inputs), then storage and sync, then the screens. A module never reaches into another's internals. Every file under `src/app/`, at any depth, is a `.ts` module named by its path, in a move or written new, formatted by Prettier, with a comment on every export. Since r51 `tests/hygiene.js` holds each module to its layer in the list below, the one place the layers are written: an import goes only to the same layer or below, a new module is added to the list, and no import goes round in a circle (the bundle turns a module's `const` into `var`, so in a circle a value read before its module has run is `undefined`, not an error).

Layer 0, config and record shapes: config, types
Layer 1, data: util, units, library, routines, formulas, records, gym, profile, model
Layer 2, engine and analytics: session, loads, prs, trend, volume, goals, importing, format, charts, analytics, time, weeks, coach, engine
Layer 3, storage and sync: chunks, merge, store, live
Layer 4, screens: layout, icons, feedback

- **Screens as components**, one per tab, reading copy and labels from one place.

## How it gets there: the legacy code shrinks

The current code is the **legacy script**: `src/10-*.js` to `src/29-*.js`, joined in name order, still wrapped in its original `(function(){ ... })()` so every `const` and `let` behaves exactly as written. `scripts/join.js` puts `src/09-imports.js` before it: the real `import` lines through which the legacy script reads what has moved to `src/app/`. Each phase moves code out of the legacy parts into modules and deletes the old copy in the same change, so nothing exists twice.

`scripts/depmap.js` parses the legacy script and lists every top-level declaration, what it uses, which values are shared mutable state, and which declarations are pure (no browser, no shared state, all the way down) and can move as they are.

**The ratchet:** the legacy script may never grow. `tests/hygiene.js` fails when it has more top-level declarations or more lines than the numbers below, and also when it has fewer, until the numbers are lowered to match, so each phase locks in what it moved. A change that adds code adds it in `src/app/`.

## The phases

Each phase is its own pull request, tried in the preview before V merges it. Each proves it changes nothing a lifter sees: the full suite in Chromium and WebKit, `tests/coherence.js`, and for the engine and analytics the 2,000 seeded histories of `tests/r36.js` giving identical numbers before and after.

1. **Toolchain and config (r49).** esbuild, TypeScript, `src/app/config.ts`, the version people see (2.0) apart from the build, the single-source and boundary checks, the ratchet. Done in r49.
2. **Pure math and data (r50).** The bottom layers, 109 declarations that read nothing but their arguments, each other and (for `uid` and `today`) the clock and a random number: `util.ts` (text, ids, dates, numbers, the sync hash), `units.ts` (units and plates), `library.ts` (muscles, joints, equipment, the exercise library and what an exercise is), `routines.ts` (the default plan and the ready-made routines) and `formulas.ts` (the 1RM estimate and its inverses, the working load, set counting, the time model and the thresholds behind trends and breaks). Moved as they were: `tests/moved.js` compares each with the same declaration in r49 after esbuild's printer, so types and layout are free and every expression and literal must match, and a one-value change fails it; it also holds every name the moved code uses to what it meant in r49 and allows nothing else at a moved module's top level (an independent review found five ways to change behaviour that passed a comparison of text alone, and each now fails). The bundle gained a "use strict" at its top: the modules ran in sloppy mode inside esbuild's wrapper, where ES modules are always strict. The pure functions that still read a setting or the log (the load step in the unit on screen, the analytics) wait for phase 3. Done in r50.
3. **State with one owner**, in two releases (V, 2026-10-17: six releases from here, grouped only where grouping adds no risk).
   - **3a (r51): the rest of the self-contained code, and one owner for the shared state.** Done in r51, as planned below.
   - **3b (r52): the engine and analytics take what they read as arguments.** Planned in detail below (Phase 3b in detail). `suggest`, `IDX()` and the readers around them stop reaching for `state` and the settings and are passed them, so they become pure functions with unit tests of their own; `tests/r36.js` (2,000 seeded histories) proves every number unchanged.
4. **Storage and sync (r53), alone.** Same storage keys, same sync documents, same key order: `tests/seams.js`, `tests/migration.js` and every baseline hold them to it. Nothing rides along: a fault across devices must have one suspect, and the log is the one thing that cannot be repaired afterwards.
5. **Screens (r54 to r56).** As components, two tabs a release: Settings and History, then Plan and Stats, then Today and the session screen last, alone, since it is used mid-workout. The legacy script is deleted when it is empty.

`format.ts` and `charts.ts` move down to layer 2, a change to the layer list and nothing else: both import only `util`, and the engine's sentences use `format.ts`'s `repSpan` and `rangeWords` and the weekly averages `charts.ts`'s `firstDate`, which a layer 2 module cannot import from layer 4. The date words join `format.ts`, so dates are worded in one module. Moving a type between modules changes no code (types leave nothing at run time), and `tests/moved.js` compares code only.

**The model.** `Model` is `{ s, today, c }`: `s` the log (typed as `EngineState`, the fields listed above and no others, so the type checker refuses a read of any other field), `today` a function giving the date the engine reads as today, and `c` the caches under their r51 names, starting as r51's did (`freshCaches()`: every one `null` except `_bwRef`, which is `undefined`, since `bwRef` tests for `undefined` and a `null` there would leave every bodyweight lift without its bodyweight). `modelOf(s, today)` makes one for a test. The types of the cached values (`IDX()`'s result and the records in it) are declared in `model.ts`, since a type the engine infers from a cache it also fills would refer to itself. `src/app/store.ts`'s `State` is typed field by field for the fields the engine reads, as its comment promised for 3b; the rest of it stays open until `normalize()` moves in phase 4.

**Pure functions.** Every moved function that reads the log, the date or a cache, directly or through another, takes the model as its first parameter, always named `M`, and its name gains `In` (`suggestIn(M, exId, plan, opts)`): 96 of them. A function taking the model is known by that first parameter, not by its name (the legacy script already has `loadIn`, `numIn` and `distIn`, which have nothing to do with it). The 16 that read none of it (`dtf`, `fmtWith`, `fmtDate`, `calSummary`, `idxAutoLighter`, `idxLightWeeks`, `lastOf`, `avgWeeksTxt`, `musTrend`, `chkWord`, `sgBadDay`, `sgNoStep`, and the tables `DTF`, `CAL_WEEKS`, `CHK_Q`, `SIZE_MAP`) move unchanged under their own names. `invalidate` becomes `invalidateIn(M)`. Inside a function taking the model exactly five things change, and nothing else may:

1. `state` is `M.s`;
2. `today()` is `M.today()`;
3. a cache `X` is `M.c.X`;
4. a call to a moved reader `f(a, b)` is `fIn(M, a, b)`;
5. the one place a reader is passed as a value, `big.map(exName)` in `coach`, is `big.map(id => exNameIn(M, id))` (`exName` takes one parameter and no moved code reads `arguments`, so the extra index and list `map` passes change nothing).

Types are added, and TypeScript's `noUnusedLocals` refuses nine declarations as written, which are pruned and listed: the seven cases `sgEasy` to `sgReps` each destructure all 31 fields of the context `C` and use a few, `idxLift` destructures `exWin` and does not use it, and `suggest` computes a date `T` it never reads. The unused names and the one unused statement are dropped. `M` is reserved: no r51 declaration in the set and no module uses the name, and in the modules it may be bound only as the first parameter of a function taking the model, never assigned.

**Marks TypeScript cannot check, and where they are counted.** The moved code relies in many places on a fact established in another statement: a list filtered to rated sets is then summed by its RIR (`tr.reduce((a, p) => a + p.rir, 0)`), three sessions all checked for a top RIR are then compared by it. Strict TypeScript cannot follow such a fact and refuses the arithmetic (TS2531), so each place needs a `!` or a cast, or the code would have to change, which a move may not do; a type that pretends the value is never null would be untrue. The review of the second draft counted more than 20 such places by reading; the exact number is the type checker's. These marks are not new escape hatches: each records an assumption the code already made, now visible, with a comment saying where the fact is established. So they are counted apart from the rest: a cast or `!` inside a declaration that a move compares token for token with its baseline counts against that move's own number in this file, recorded when the move is made and only falling afterwards, and every other one counts against the numbers in The outside review, which only fall. `tests/hygiene.js` decides which is which from the baseline itself (a declaration in a module whose name, less the `In` of a function taking the model, was a legacy declaration in r51), so a mark in new or changed code can never ride on a move. The three casts `Object.create(null)` needs (TypeScript types it any; `EX`'s map and two in `rirUsual`) are among them. `Array(n).fill(...)` takes its element type instead (`Array<number>(n)`), which needs no mark and changes no code.

**The live model.** `src/app/live.ts` (layer 3, beside the store) holds the one model the app runs on, `LIVE`: `s` is a getter returning the store's `state` binding, so a log replaced by `setState` is read at once, as now; `today` is `util`'s own `today`, so the date is read at every call, as now (an app resumed the next morning without a reload reads the new date); `c` is its caches, built on first use and cleared by `invalidate`, exactly as r51's. One object, made once: no call makes an object or reads the clock unless the engine reads it. `live(f)` turns a pure function into the app's: it returns `(...args) => f(LIVE, ...args)`, so every argument is passed on as before (the four places the legacy script passes a reader as a value, `recentExIds(8).map(EX)` among them, get the same arguments). An adapter has no name and a length of 0, and nothing in the source or the tests reads either. For each of the 74 moved names the legacy script calls (73 readers and `invalidate`), `live.ts` exports `export const X = live(XIn);`, and the legacy script imports `X` from it in `src/09-imports.js`, so not one call in the screens changes; of the 16 unchanged declarations it imports the 8 it uses (`fmtWith`, `fmtDate`, `CAL_WEEKS`, `SIZE_MAP`, `avgWeeksTxt`, `musTrend`, `chkWord`, `CHK_Q`) from their modules.

**Proof, before V sees it:**

1. **The code is r51's.** `tests/moved.js` reads each module's code back before comparing it with r51's, on the syntax tree: a function taking the model loses `In` and its first parameter `M`; a call `fIn(M, ...)`, whose first argument must be `M` itself, is `f(...)`; `M.s` is `state`, `M.today` is `today` and `M.c.X` is `X`; and `id => exNameIn(M, id)` is `exName` only where the reader takes that one parameter. After the read-back no `M` and no reference to a function taking the model may remain, so any other use of the model fails (a nested `M`, `M['s']`, `M.c` or `M` passed whole, a spread, a call without `M`, a reader used as a value). On r51's side the nine listed prunes are applied from a fixed list, each verified: every dropped name is never read in its declaration; `C` is a constant bound to an object of shorthand plain values in `suggestCore`, the only caller of each case in both builds; `trendScope` returns an object literal; and the dropped statement in `suggest` reads `opts.before`, whose callers all pass an object literal, and calls `isDate` and `today`, which change nothing. Then the comparison is token for token, as for every move since r50, for the 96 functions taking the model, the 16 unchanged and `invalidateIn`. What has no r51 counterpart is held to its exact code with an executable check, as `added` entries: `freshCaches` (the seven caches and their starting values, `_bwRef` `undefined`), `modelOf`, `LIVE` (its `s` is the store's log after `setState`, its `today` is `util`'s `today` itself) and `live` (it passes `LIVE` and then every argument and returns what the function returns); every other declaration in `live.ts` must be `export const X = live(XIn);` for exactly the names the legacy script imports, no more and no fewer. The legacy script left behind is r51's, statement for statement, less the moved declarations and the caches (listed as retired, their place taken by `freshCaches`), and less the 22 names added to the test hook (item 3).
2. **Nothing behind the model's back** (`tests/hygiene.js`). Every function taking the model, and every declaration it reaches through any reference (a call, or a function passed as a value such as `.filter(isWork)` or `.sort(sessCmp)`) and import in any module, reads no clock (`today`, `Date.now`, a `new Date()` with no arguments, `performance`), nothing random (`Math.random`, `uid`, `crypto`), no browser global (`window`, `document`, storage, `indexedDB`, `navigator`, `location`, timers, `fetch`, `globalThis`), nothing from `store.ts` or `live.ts`, and no mutable value kept at a module's top level other than `DTF`, a store of date formatters that changes no result: the model is its only source of the log, the date and the caches. `Intl` is allowed and listed, since the engine's sentences word dates in the phone's language. By the review's measurement on r51's code, the 92 module declarations the moved code reaches pass. The check is shown failing on a planted read of each kind, including one reached through a helper in another module and one through a function passed as a value. `scripts/depmap.js` reads a name imported from `live.ts` as a read of shared state, so a screen that calls `EX` is not counted as pure.

The engine's modules bundled for Node, with no page: the normalized histories of item 3 (taken from the page, since `normalize()` stays in the legacy script until phase 4) deep-frozen, the language and time zone set to the page's. Each of the 74 on a fresh model gives the page's answer, gives it again on a second fresh model, and writes nothing to the log (a write to a frozen log throws); the functions only the engine calls (`sgEasyIn`, `idxLiftIn` and the like) are reached through them, and how much of each module runs is what the coverage measures. 5. **Everything else.** `tests/r36.js` unchanged (r35 against this build), `tests/coherence.js`, `tests/perf.js` (`live` adds a call and an argument list to the readers the screens call most, about 20 to 30 billionths of a second a call in V8 by the review's measurement and not measured in Safari's engine, so tick, Today, Stats and the rebuild are measured before and after and reported; each stays under its ceiling), and every suite in Chromium and WebKit.
6. Independent reviews before the pull request, each finding closed and replayed to a failure.

That is the standard answer: a check cannot guard its own text. `main` is protected (`OWNER.md` B6, done 2026-10-15): a merge needs a pull request and the `test` check green, so that review is where every such edit is seen.



## Rules (each enforced by a test, not by memory)

- Moving code changes no code: `tests/moved.js` holds every moved declaration to the build its phase started from, token for token once types, layout and whitespace are set aside, with every name in it pointing where it did; a moved module holds only imports under their own names and exported declarations, and no other module exports a name that was moved. The legacy script a phase leaves behind is the baseline's, statement for statement and in order, once the rewrites the phase lists are read back. A declaration a phase adds or changes on purpose is listed with the reason and an executable check of what it does.
- Moved code exists once: no legacy declaration takes a module export's name (it would hide the module's copy), every export the legacy script uses is imported, every import is used, and every name the legacy script reads without declaring or importing it is on a list of browser and JavaScript globals, so a missing import fails before the app runs (`tests/hygiene.js`, from `scripts/depmap.js`'s scope-aware reading of the legacy script). An imported name that is shared state (exported with `let`, or written by the legacy script) makes its readers impure in the map.

- A value that names, identifies or configures the app is defined once, in `src/app/config.ts`, and read everywhere else. `tests/hygiene.js` fails on the name, the site address, a build id or the storage id typed anywhere else, in code or markup.
- `src/app/` imports only `src/app/`. The legacy parts import only through `src/09-imports.js`.
- The legacy script never grows, in declarations or in lines (the ratchet above).
- Types say only what is true: no value in `src/app/` has a type that is any or holds it as a union member or type argument, by the type checker (within the reach item 1 of The outside review states); every cast and `!` has a comment naming it, and no cast's written type names a type parameter around it; the casts, `!` and open types only fall in number (the ratchet in The outside review); every `catch` in a module throws or carries a comment (`tests/hygiene.js`).
- Outside addresses, library versions, the font faces and their weights are config's, like the name, in the source, the scripts and the test fixtures; any other outside address waits in The outside review's list for its phase (`tests/hygiene.js`).
- Nothing a screen sets up outlives the render that drew it: charts, drag lists, intervals and the 3D body's one WebGL context (`tests/cleanup.js`).
- Storage keys keep "ironlog" whatever the app is called: they are built from `STORAGE_ID`, an identifier that never changes, since renaming it would leave saved logs behind. `tests/r49.js` holds the keys to their exact values.
- Moving code changes no behaviour: the suites, the coherence checks and the r36 equivalence say so before a phase is merged.
